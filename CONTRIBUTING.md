# Contributing to TenderBomb

Этот файл фиксирует рабочие правила репозитория, чтобы история Git оставалась читаемой, а релизы — предсказуемыми.

## Основная ветка

`main` содержит рабочую версию проекта.

Новые изменения рекомендуется делать в отдельных ветках:

- `feat/<name>` — новая функциональность;
- `fix/<name>` — исправление ошибки;
- `docs/<name>` — документация;
- `refactor/<name>` — рефакторинг без изменения поведения;
- `chore/<name>` — обслуживание проекта и инфраструктуры.

## Формат коммитов

Используем Conventional Commits:

```text
<type>(optional-scope): short description
```

Основные типы:

| Type | Когда использовать |
|---|---|
| `feat` | новая функция или игровая механика |
| `fix` | исправление бага |
| `docs` | README, changelog, документация |
| `refactor` | изменение структуры кода без новой функции |
| `style` | форматирование без изменения логики |
| `perf` | оптимизация производительности |
| `test` | тесты |
| `build` | сборка и упаковка |
| `chore` | обслуживание репозитория |

Примеры:

```text
feat(casino): add progressive jackpot
fix(tanks): prevent duplicate credit reward
docs: document LAN server startup
refactor(server): extract profile persistence
chore(release): prepare v0.1.6
```

Не рекомендуется использовать сообщения вида:

```text
fix
update
small fixes
0.1.6
новая версия
```

Сам номер версии относится к релизу, а коммит должен объяснять, **что именно изменилось**.

## Pull Request

Перед слиянием:

1. Изменения запускаются локально.
2. Проверены затронутые игровые режимы.
3. В репозиторий не попали временные файлы, логи и локальные данные.
4. Если изменение заметно пользователю — обновлён `CHANGELOG.md`.
5. Заголовок PR кратко описывает результат.

Для небольшого solo-проекта допустим squash merge — тогда история `main` остаётся компактной.

## Версии

TenderBomb использует Semantic Versioning:

- **PATCH** — исправления без новой функциональности: `0.1.5 → 0.1.6`;
- **MINOR** — новая совместимая функциональность: `0.1.6 → 0.2.0`;
- **MAJOR** — крупные несовместимые изменения: `0.x → 1.0.0`.

До версии `1.0.0` проект считается активно развивающимся.

Подробный процесс релиза описан в [docs/RELEASING.md](docs/RELEASING.md).
